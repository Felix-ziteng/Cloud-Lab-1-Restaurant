# 开店启动手册

给店里日常"开机启动系统"用的操作文档：怎么把服务器跑起来、每个界面在哪、密码/账号是什么。
不是给开发用的技术文档（技术架构见 `docs/ARCHITECTURE.md`）。

## 一、启动步骤（每天开店前做一次）

1. **打开 Docker Desktop**（任务栏图标，或开始菜单搜"Docker Desktop"），等它右下角图标变成"running"状态（大概 10-20 秒）。
2. **启动数据库容器**：打开终端，执行
   ```
   docker start restaurant-postgres-1
   ```
3. **启动后端服务**：在项目根目录 `c:\dev\Restaurant` 执行
   ```
   npm run dev:backend
   ```
   看到类似 `Nest application successfully started` 就说明起来了，监听 3000 端口。
4. **启动前端服务**：另开一个终端，同样在项目根目录执行
   ```
   npm run dev:frontend
   ```
   看到 `Local:` 和 `Network:` 两行地址就说明起来了，监听 5173 端口。

这两个服务（第 3、4 步）要一直开着终端窗口不关，关掉终端服务就停了。以后如果要写成"双击就启动、不用开终端"的脚本，再单独说。

**验证是否都起来了**：浏览器打开 http://localhost:5173/kitchen，能看到"厨房看板"页面（哪怕是空的）就说明前后端都正常。

## 二、各个界面的网址

店里所有设备（前台电脑、厨房平板、点餐平板、顾客手机）要跟运行服务的这台电脑连在**同一个 WiFi/局域网**下，用这台电脑的局域网 IP 访问，不是 `localhost`。

**这台电脑当前的局域网 IP 是：`192.168.1.134`**（记录于 2026-09-04）。这个 IP 由路由器分配，重启路由器/电脑后可能会变——如果哪天所有设备突然连不上，先在这台电脑上打开终端执行 `ipconfig`，找 WLAN 那一栏的 IPv4 地址，看看是不是变了。IP 变了之后，`apps/frontend/.env` 里的 `VITE_API_BASE_URL` 也要跟着改成新 IP，然后重启前端服务（第一部分第 4 步）才会生效。

### 桌台点餐台开台密码

**每张桌自己有一个固定的 4 位数字密码**（不再是全店统一一个），建议贴在桌上（跟以后要加的 WiFi/菜单二维码放一起）。服务员随手拿一台平板给客人，在平板上直接输入这张桌的密码：

- 这张桌当前空闲 → 平板会让你填一下人数，确认后开台。
- 这张桌已经有人在用了（比如前台已经手动开过台，或者已经有另一台平板在服务这一桌）→ 平板直接接入这张桌现有的点单会话，不用重新填人数——所以一桌人多、需要好几台平板同时点菜，或者前台先开了台后面才想起来给一台平板，都不受影响。

这个密码只是防客人瞎捣乱，不是什么高强度安全机制。**当前各桌密码**（2026-09-04 迁移时按桌号顺序生成的默认值，店长可以在"前台 → 管理 → 桌台/包间管理"里逐桌改成自己想要的号码，改的时候界面上就能直接看到当前密码）：A1=`1234`、A2=`1235`、A3=`1236`、B1=`1237`（测试用的 ZZ- 开头几桌另有编号，不列在这里）。新增桌台时店长在同一个页面里手动填一个还没被别的桌占用的 4 位密码。

### 数据库/服务器相关的密码（一般不需要用到）

数据库密码、JWT 签名密钥这些是纯技术层面的配置，存在 `apps/backend/.env` 文件里，日常开店操作用不到，只有我或者以后接手的开发者调整服务器配置时才需要看。这些目前还是开发阶段用的默认值，正式对外营业前需要换成随机生成的强密码——见 `docs/ARCHITECTURE.md` 里关于生产环境准备的部分。

## 四、常见问题

- **前端起来了但页面里一直转圈/请求失败**：八成是 `apps/frontend/.env` 里的 IP 跟这台电脑现在的局域网 IP 对不上了（比如电脑换了 WiFi、路由器重启分配了新 IP）。按第二部分说的重新查 IP、改配置、重启前端。
- **平板/手机打不开网址**：先确认它跟电脑连的是同一个 WiFi，不是手机自己的移动数据。
- **忘记店长 PIN 了**：这个只能去数据库里直接改，联系开发者处理，不属于日常操作范围。
